01 / THE IDEA

一个页面，只讲一个重点。

先想听众要记住什么，再决定页面上放什么。

你负责提出观点，
画面负责让观点
更容易被理解。

讲述细节，留给你的声音。

  • 01标题说出核心判断
  • 02图像或证据解释判断
  • 03讲稿补充过程与边界
一个实用检查：看完这一页，听众能用一句话复述什么？
设计建议 · 并非实验结论02 / 07
约 45 秒。页面不必承载逐字讲稿。先给出观点，再用证据或示意解释；复杂内容可拆成几页。这里的排版原则是实践建议，不应作为已有研究结论引用。
02 / THE STRUCTURE

材料不是故事，组织之后才是。

从“我查到了什么”，走向“我想说明什么”。

01

提出问题

为什么值得讨论？
与听众有什么关系？

02

给出证据

材料支持什么观点？
依据从哪里来？

03

解释边界

还有什么不能确定？
可能有哪些反例？

04

留下结论

最该记住的一句话？
下一步能做什么？

问题 → 证据 → 边界 → 结论03 / 07
约 50 秒。按从左到右的顺序讲。这个结构适合许多课堂报告，但不是强制章节。实验课可突出方法与结果，文献课可突出观点与分歧。过渡：结构确定之后，再选择适合内容的画面。
03 / VISUAL EXPLANATION

有关系的内容，用图来讲。

HTML 可以把流程、结构和比较，直接变成可读的画面。

视觉不只是装饰。

箭头表达顺序，
分组表达归属，
大小与颜色表达重点。

先确定关系，再选择图形。

结构示意 · SVG 矢量绘制04 / 07
约 45 秒。用图示讲述“材料、论点、表达”的依赖关系。强调图形必须编码信息。这一页的 SVG 没有外部依赖，离线可用，打印时也会保留。
